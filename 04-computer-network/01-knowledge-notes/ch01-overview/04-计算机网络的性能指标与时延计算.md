# 04-计算机网络的性能指标与时延计算（1.6 节）

> **30秒速记卡**：
> - **速率 vs 带宽 vs 吞吐量**：速率是瞬时跑的比特率（$10^3$ 进制）；带宽是链路物理上限（理论最大速率）；吞吐量是实际通过的数据量（$\text{吞吐量} \le \text{带宽}$）。
> - **时延四兄弟**：$\text{总时延} = \text{发送时延} + \text{传播时延} + \text{处理时延} + \text{排队时延}$。
> - **两大必考计算**：
>   - 发送时延（传输时延）：$t_{\text{trans}} = \frac{L \text{ (bit)}}{R \text{ (bit/s)}}$（收费站发车，受带宽决定）。
>   - 传播时延：$t_{\text{prop}} = \frac{D \text{ (m)}}{V \text{ (m/s)}}$（公路跑车，光纤中 $V \approx 2 \times 10^8 \text{ m/s}$，受物理距离决定）。
> - **时延带宽积**：$\text{传播时延} \times \text{带宽}$（管道最大比特容量）。
> - **利用率恶化公式**：$D = \frac{D_0}{1 - U}$（利用率 $U \to 1$ 时，排队时延急剧趋于无穷大）。

## 速率、带宽与吞吐量精析

| 指标名称 | 物理含义与比喻 | 单位 | 核心进位与限制 |
| :--- | :--- | :--- | :--- |
| **速率 (Speed)** | 每秒在信道中传输的二进制比特数。 | $\text{bit/s}, \text{Mb/s}, \text{Gb/s}$ | 通信按十进制（$1\text{ Mb/s} = 10^6\text{ b/s}$）。 |
| **带宽 (Bandwidth)** | 链路在单位时间内能够通过的**最高理论数据率**。 | $\text{bit/s}$ | 反映物理信道的数据承载极限。 |
| **吞吐量 (Throughput)** | 单位时间内实际通过某个网络/接口的数据量。 | $\text{bit/s}$ 或 $\text{B/s}$ | 受网络拥塞与服务端限制，$\text{吞吐量} \le \text{带宽}$。 |

## 核心时延计算体系

数据的端到端总时延由以下 4 部分构成：
$$\text{总时延} = \text{发送时延} + \text{传播时延} + \text{处理时延} + \text{排队时延}$$

### 1. 发送时延（传输时延，Transmission Delay）
- **物理过程**：主机或路由器把数据块的所有比特推上物理信道所需的时间（“收费站逐车放行”）。
- **计算公式**：
  $$t_{\text{trans}} = \frac{\text{数据帧长度 } L \text{ (bit)}}{\text{发送速率 / 带宽 } R \text{ (bit/s)}}$$

### 2. 传播时延（Propagation Delay）
- **物理过程**：电磁波在光纤或铜线等物理介质中传播一定距离所需的时间（“车辆在公路上疾驰”）。
- **计算公式**：
  $$t_{\text{prop}} = \frac{\text{物理信道距离 } D \text{ (m)}}{\text{电磁波传播速率 } V \text{ (m/s)}}$$
  *(光纤中光速一般按 $V = 2.0 \times 10^8 \text{ m/s}$ 计算)*

### 3. 处理时延与排队时延
- **处理时延**：路由器解析包头、校验差错、查找路由转发表所花费的时间。
- **排队时延**：数据包在路由器输入/输出缓存队列中等待调度转发的时间。

## 时延带宽积、往返时间 RTT 与利用率

### 1. 时延带宽积（管道容积）
$$\text{时延带宽积} = \text{传播时延} \times \text{带宽}$$
- **物理意义**：代表这根物理链路充满比特时，能够容纳的最大数据量（以 bit 为单位的物理管道体积）。

### 2. 往返时间 RTT 与 有效数据率（Effective Data Rate）
- **RTT（Round-Trip Time）**：从发送方发出数据，到收到对端 ACK 确认信号所耗费的双向总时间（常用于 `ping` 诊断）。
- **有效数据率计算模型（考虑停等确认）**：
  $$\text{有效数据率} = \frac{\text{传输的数据量}}{\text{实际总耗时}} = \frac{\text{数据长度 } L}{\text{发送时延 } t_{\text{发送}} + \text{往返时间 RTT}}$$
  *(注：确认包通常极短，忽略其发送时延)*

> 📘 **课件典型例题**：
> 主机 A 向 B 发送 $100\text{ MB}$ 数据，链路带宽 $100\text{ Mbit/s}$，两节点间 $\text{RTT} = 2\text{ s}$。计算有效数据率：
> 1. 发送时延 $t_{\text{发送}} = \frac{100 \times 2^{20} \times 8 \text{ bit}}{100 \times 10^6 \text{ bit/s}} \approx 8.39\text{ s}$
> 2. 总耗时 $= 8.39\text{ s} + 2\text{ s} = 10.39\text{ s}$
> 3. $\text{有效数据率} = \frac{100 \times 2^{20} \times 8}{10.39} \approx 80.7\text{ Mbit/s}$（利用率由理论 100% 降至 80.7%）

> 💡 **后端开发与架构视点（为什么后端极度厌恶频繁 RTT？）**：
> 在开发微服务或数据库调用时，若在一个循环里逐条发单条查询（著名的 **N+1 查询**）：
> - 每条数据很小（发送时延才 0.01 ms），但跨机房 RTT 可能有 2~5 ms。
> - 100 次循环就要白白浪费数百毫秒去“空等 RTT”！
> - **解决方案**：后端采用**批量接口（Batch API / IN 查询）**、**连接池复用**以及 **HTTP/2 多路复用**，核心思想都是平摊或并发消除等待 RTT 导致的性能雪崩。

### 3. 利用率与时延急剧恶化模型
$$D = \frac{D_0}{1 - U}$$
*(其中 $D_0$ 为网络完全空闲时的基准时延，$U$ 为信道利用率，$0 \le U < 1$)*

```
时延 D
  ▲
  │                                    /
  │                                   /
  │                                  /  <-- 利用率接近 1 时，时延暴增至无穷大
  │                           ______/
  │__________________________/
  └───────────────────────────────────────► 信道利用率 U
 0%                         50%         100%
```
- **架构启示**：生产环境中核心骨干网与服务器带宽的利用率通常需控制在 50% 以下，防止流量突发引发排队崩溃。

## 计算机网络非性能特征速查卡

1. **费用**：建设与运营成本。
2. **质量**：QoS（服务质量）、丢包率与网络抖动。
3. **标准化**：国际 RFC 标准兼容性。
4. **可靠性**：双路冗余与快速故障倒换。
5. **可扩展性**：面对并发激增平滑水平扩容的能力。
6. **易于管理维护**：自动化监控与可观测性支持。

## 易错点与经典避坑

| 易错题型 | 坑点描述 | 避坑秘籍 |
| :--- | :--- | :--- |
| **“高速链路比特跑得更快”** | 误以为高带宽能缩短传播时延。在 1000 km 光纤中，1 B 数据的传播时延恒为 5 ms；带宽哪怕从 1 Mbps 狂飙到 1 Gbps，总时延也仅从 5.008 ms 变成 5.000008 ms。**提高带宽只能缩短发送时延，信号在介质中的传播速度永远不变**。 | 计算题必先分清发送时延 vs 传播时延！ |
| **存储单位 vs 通信进位混淆** | $100\text{ Mbps}$ 误算为每秒可下 $100\text{ MB}$。 | 存储为 $2^{10}=1024$ 进位，通信为 $10^3=1000$ 进位。理论下载速度约为 $\frac{100}{8} = 12.5\text{ MB/s}$。 |

## 知识网络关联
