3. 假定某信道受奈氏准则限制的最高码元速率为30000码元/秒。如果采用振幅调制，把码元的振幅划分为16个不同等级来传送，那么可以获得多高的数据率（bit/s）
   A. 80000
   B. 100000
   C. 120000
   D. 180000

---

### 题目解析与答案

- **【正确答案】**：C. 120000

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把网络传输想象成**高速公路运送货物**：
  1. **码元传输速率（30000 码元/秒） = 高速公路上跑的“货车流速”**：  
     题目说每秒最多跑 30000 辆货车（受限于物理规律，路上车流量到了极限，无法再开更多车）。
  2. **振幅划分为 16 个不同等级 = 每辆货车里装了多少“集装箱（bit）”**：  
     计算机世界里只有二进制的 0 和 1。如果用不同的信号振幅区分出 16 种不同状态，那么需要几位二进制才能表达 16 种状态？  
     因为 $2^4 = 16$（即 $\log_2(16) = 4$），用 4 位二进制（4 个 bit，如 0000 到 1111）就能精准对应这 16 个等级！因此，**每 1 辆货车（每个码元）内部整整塞下了 4 个 bit**。
  3. **数据率（bit/s） = 最终每秒送达的“集装箱总数”**：  
     既然 1 秒跑 30000 辆车，每辆车装 4 个 bit，那么 1 秒钟运送的 bit 总数就是：$30000 \times 4 = 120000\text{ bit/s}$。

- **【手把手计算 / 解题步骤】**：
  1. **明确已知物理量**：
     - 最高码元速率 $R_B = 30000\text{ Baud}$（波特，即码元/秒）。
     - 码元离散状态数（调制等级）$M = 16$。
  2. **求单个码元所携带的信息量（bit 数）**：
     根据信息论与二进制编码原理，每个码元能携带的比特数 $n$ 为：
     $$n = \log_2(M) = \log_2(16) = 4\text{ bit}$$
  3. **计算最高数据率 $C$**：
     根据数据传输速率计算公式（波特率与比特率的关系）：
     $$C = R_B \times \log_2(M) = 30000 \times 4 = 120000\text{ bit/s}$$
     因此可获得的数据率为 $120000\text{ bit/s}$。

- **【各选项逐一深度剖析】**：
  - **A. 80000**：错误。若算成 80000，通常是误将 $M=16$ 错误折算或者计算失误，无法由标准公式得到。
  - **B. 100000**：错误。无任何计算依据的凑数干扰项。
  - **C. 120000**：**正确**。由 $30000 \times \log_2(16) = 30000 \times 4 = 120000\text{ bit/s}$ 精确得出。
  - **D. 180000**：错误。常见计算陷阱是混淆了调制等级与进制关系，比如误以为 $n=6$（$30000 \times 6 = 180000$，但 $2^6 = 64$ 而非 16）。

- **【期末防坑提示】**：
  1. **分清“波特率（Baud）”与“比特率（bit/s）”**：
     - 波特率（码元/秒）：只算**每秒发送了多少个波形脉冲（货车数）**，不管里面装了多少货。
     - 比特率（信息速率）：算的是**每秒发送了多少个二进制位 0/1（货物总量）**。
     - 换算核心桥梁：$$\text{比特率} = \text{波特率} \times \log_2(M)$$（$M$ 为码元的离散状态数/调制等级）。
  2. **警惕奈氏准则原公式的“乘 2 陷阱”**：
     - 奈奎斯特准则原始公式为 $R_{B\max} = 2W$（波特），其最高数据率公式写作 $C = 2W \log_2(M)$。
     - **特别注意**：本题题干已经直接给出了“受奈氏准则限制的最高码元速率为 30000 码元/秒”（即出题人已经把 $2W$ 算好了，直接告诉你 $R_B = 30000$），**千万不要再去乘以 2**！如果多乘了个 2 就会算出 240000。

4. (单选题, 5分) UDP 报文头部格式中不包括（ ）？
   A. 目的IP地址
   B. 报文长度
   C. 目的端口号
   D. 源端口号

---

### 题目解析与答案

- **【正确答案】**：A. 目的IP地址

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把网络传输想象成**寄快递送到大学宿舍具体某个人手上**：
  1. **网络层（IP 协议）负责“学校到学校”（主机到主机，Host-to-Host）**：  
     包裹外壳最醒目的“寄件学校地址（源 IP）”和“收件学校地址（目的 IP）”，是写在**网络层的 IP 数据报首部**上的。快递物流车只负责把包裹从清华大学送到北京大学校门。
  2. **传输层（UDP 协议）负责“宿舍到宿舍 / 人到人”（进程到进程，Process-to-Process）**：  
     包裹进了学校大门后，到底该送给哪个宿舍的哪位同学？这需要具体的**房间门牌号（端口号 Port）**！电脑里运行着许多软件（微信、QQ、浏览器、游戏），端口号就是区分这些具体程序的门牌号。
  3. **职责清晰分工**：  
     UDP 作为传输层的协议，它只关心“从哪个门牌号发的（源端口）”以及“送给哪个门牌号（目的端口）”。至于包裹送去哪个学校（目的 IP 地址），那是楼下网络层 IP 协议操心的事情，**UDP 头部里根本不需要也不包含 IP 地址**。

- **【核心机制与字段结构手把手拆解】**：
  UDP 首部格式极其简洁轻便，仅占用 **8 个字节（64 位）**，固定由 4 个字段组成，每个字段刚好占 **2 个字节（16 位）**（期末必背 4 字口诀：**“源、目、长、检”**）：
  1. **源端口号（Source Port，16 位 / 2 字节）**：发送方进程的端口号，需要对方回信时使用，不需要时可全填 0。
  2. **目的端口号（Destination Port，16 位 / 2 字节）**：接收方进程的端口号，终点交付时必须使用（如 DNS 查询是 53 端口）。
  3. **长度（Length，16 位 / 2 字节）**：UDP 用户数据报的完整长度（包括 **首部 8 字节 + 数据载荷部分**），最小值为 8（即数据载荷为 0）。
  4. **检验和（Checksum，16 位 / 2 字节）**：用于检测 UDP 数据报在传输过程中是否有差错。发现差错通常直接丢弃。

- **【各选项逐一深度剖析】**：
  - **A. 目的IP地址**：**正确（符合题意，首部不包含）**。IP 地址属于**网络层（第 3 层）**的控制信息，封装在 IP 数据报的首部中，传输层（第 4 层）的 UDP 首部绝对不包含 IP 地址。
  - **B. 报文长度**：错误（首部包含）。UDP 首部第 3 个字段就是 16 位的“长度”字段，指明首部加数据载荷的总字节数。
  - **C. 目的端口号**：错误（首部包含）。UDP 首部第 2 个字段就是 16 位的“目的端口”，指明接收端主机的目标应用程序进程。
  - **D. 源端口号**：错误（首部包含）。UDP 首部第 1 个字段就是 16 位的“源端口”，指明发送端主机的源程序进程。

- **【期末防坑提示】**：
  1. **易混淆陷阱：“UDP 伪首部”包含 IP 地址，但伪首部不是真实首部！**  
     在计算 UDP 检验和时，临时在 UDP 报文前添加了 12 个字节的“伪首部”（里面包含了源 IP 和目的 IP）。但**伪首部既不向下传送，也不向上递交，它仅仅在计算检验和的瞬间在内存中临时存在**，绝对不属于 UDP 报文真正的头部格式！
  2. **TCP 与 UDP 头部长度对比高频考点**：
     - **UDP 头部固定且极简**：只有 **8 字节**（无任何可选扩展字段）。
     - **TCP 头部固定长度**：最小为 **20 字节**（首部长度可变，最大可达 60 字节）。
  3. **分层职能混淆**：
     - 看到“**IP 地址**” $\rightarrow$ 一律归属于**网络层**（如 IPv4 首部、IPv6 首部）。
     - 看到“**端口号**” $\rightarrow$ 一律归属于**传输层**（TCP / UDP）。

5. (单选题, 5分) 在TCP 报文段的报头中，窗口字段的作用是（ ）？
   A. 报头中32bit 字节的数量
   B. 说明对方端口的数量
   C. 说明网络的负荷能力
   D. 控制对方的发送流量

---

### 题目解析与答案

- **【正确答案】**：D. 控制对方的发送流量

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把网络传输想象成**大胃王朋友喝奶茶（流量控制） vs 整座城市的高架桥堵车（拥塞控制）**：
  1. **TCP 报头里的“窗口字段” = 朋友嘴里还能喝几毫升奶茶（接收窗口 rwnd）**：  
     你（发送方）拿着奶茶壶使劲倒，朋友（接收方）的嘴和胃（接收缓存）只有那么大。为了防止奶茶溢出来（缓冲区溢出导致丢包），朋友每次换气时都会举牌告诉你：“**窗口 = 300 毫升**”！  
     这句话就是明确**限制你倒奶茶的速度与数量**——这就叫**控制对方的发送流量（流量控制）**。
  2. **为什么不是“网络的负荷能力”？**  
     “网络的负荷能力”指的是整座城市的高架公路堵不堵车（**拥塞控制**）。公路堵不堵，并不是靠接收方在报头里写出来的，而是**发送方自己在心里根据路况估算出来的（拥塞窗口 cwnd）**，**TCP 报头里根本没有专门记录网络负荷的字段**！

- **【核心机制与字段结构手把手拆解】**：
  1. **窗口字段的定义**：  
     在 TCP 报头中，**窗口字段（Window Size）**占 **16 位（2 字节）**，其数值单位是**字节（Byte）**。
  2. **工作原理（滑动窗口与流量控制）**：
     - 窗口值是**接收方告诉发送方**的一个明确数值，表示：“**从本报文段首部中的确认号算起，接收方目前允许对方发送的数据量**”。
     - 窗口字段的值是**动态变化**的。当接收方的应用程序从接收缓存中读取数据后，空闲缓存变大，接收方就会发送更大的窗口值；反之，若缓存变小，窗口值缩减。
     - 若接收方发回 `Window = 0`（零窗口），发送方必须立刻停止发送数据，直到收到非零窗口的通知。因此其核心作用就是**控制对方的发送流量**。

- **【各选项逐一深度剖析】**：
  - **A. 报头中32bit 字节的数量**：错误。这个功能对应的是 TCP 报头中的“**数据偏移**”（Data Offset，占 4 位），它指出 TCP 报文段的数据起始处距离 TCP 报文段的起始处有多远，本质就是 TCP 报头的长度（以 32 位/4 字节为一个计算单位）。
  - **B. 说明对方端口的数量**：错误。毫无依据的干扰项。TCP 报头中只有明确的“源端口”与“目的端口”（各 16 位），用于标识具体进程，并不存在“端口数量”字段。
  - **C. 说明网络的负荷能力**：**绝大多数初学者极易踩坑的经典干扰项！** 说明网络负荷能力的是**拥塞窗口（cwnd, Congestion Window）**。拥塞窗口是发送方根据网络拥塞程度（如超时丢包、RTT 变化）自己在本地内存中动态维持的变量，**并没有直接写在 TCP 报文段的报头中**；报头中显式携带的只有“接收窗口（rwnd）”，用于**端到端的流量控制**。
  - **D. 控制对方的发送流量**：**正确**。接收方通过在 TCP 报头中写入当前自身剩余的接收缓存大小（接收窗口），动态制约发送方的发送上限，从而实现**流量控制（Flow Control）**。

- **【期末防坑提示】**：
  1. **高频混淆概念：“流量控制” vs “拥塞控制”**：
     - **流量控制（Flow Control）**：**点对点（端到端）**问题。接收端太慢，怕被发送端撑爆。解决方案：TCP 报头里的 **窗口字段（rwnd）**。
     - **拥塞控制（Congestion Control）**：**全局性**问题。中间网络路由器和链路堵车。解决方案：发送方自己在内存中估算的 **拥塞窗口（cwnd）**（经由慢开始、拥塞避免、快重传、快恢复四种算法调节）。
     - **最终发送窗口上限公式**：$$\text{发送窗口} W = \min(\text{接收窗口 rwnd}, \text{拥塞窗口 cwnd})$$
  2. **窗口字段的单位防坑**：
     - 窗口字段的单位是**字节（Byte）**，绝不是“报文段个数”或“数据包个数”！

6. (单选题, 5分) 数据链路层的三个基本问题是：（ ）、透明传输和差错检测？
   A. 封装成帧
   B. 字节填充
   C. 链路终止
   D. 受控接入

---

### 题目解析与答案

- **【正确答案】**：A. 封装成帧

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把网络数据链路层传输想象成**流水线打包寄快递的“三大生存底线”**：
  1. **封装成帧（选 A） $\rightarrow$ 给散乱零件打包装箱，贴好头尾封条**：  
     物理层只负责在网线或光纤里无休止地传送 0 和 1（高低电平），就像流水线上一颗颗散落的螺丝钉。如果直接这么发，接收方根本不知道哪几颗螺丝是一套完整零件。因此链路层必须把数据装进箱子里，前面贴上“开始封条（帧首部）”，后面贴上“结束封条（帧尾部）”，明确划分出一个完整的“帧（Frame）”。这就是**封装成帧**。
  2. **透明传输 $\rightarrow$ 箱子里装什么都行，即便零件长得像封条也不误判**：  
     万一用户寄的文本或图片二进制数据里，恰好有一段内容长得跟“帧尾封条”一模一样，接收端会不会以为箱子到此结束而提前切断？为了让任何奇奇怪怪的数据都能原汁原味、不被曲解地穿过链路，链路层通过“字节填充”等机制实现**透明传输**。
  3. **差错检测 $\rightarrow$ 路上有没有摔烂，一检便知**：  
     传输途中遭遇雷电电磁干扰，某个 0 变成了 1（发生比特差错）。怎么知道货物坏没坏？在箱子尾部附上校验码（CRC 循环冗余检验），接收方一验算，如果坏了就果断扔掉重新要。这就是**差错检测**。

- **【核心机制与字段结构手把手拆解】**：
  数据链路层协议虽然形式多样（如点对点的 PPP 协议、局域网的以太网 MAC 帧等），但只要在链路上传递信息，都必须且只能围绕这三个基本问题展开设计：
  1. **封装成帧（Framing）**：规定帧的定界方式（确定帧的界限，识别哪里是头 SOH、哪里是尾 EOT）以及定义链路所允许的**最大传送单元（MTU）**。
  2. **透明传输（Transparency）**：解决数据部分可能出现的与控制定界字符冲突的问题，主要通过“**字节填充**（插入转义字符 ESC）”或“**零比特填充**（遇到 5 个连续的 1 就强行塞入一个 0）”来实现。
  3. **差错检测（Error Detection）**：通过检错码（如 FCS 帧检验序列，广泛利用 **CRC 循环冗余检验**）识别传输中的比特差错，确保丢弃损坏帧。

- **【各选项逐一深度剖析】**：
  - **A. 封装成帧**：**正确**。与“透明传输”、“差错检测”并称为数据链路层三大不可或缺的基本问题（铁三角）。
  - **B. 字节填充**：错误。属于**以偏概全的典型干扰项**。字节填充（Byte Stuffing）只是实现“透明传输”的一种具体技术手段（例如在字符异步传输中插入 ESC 转义字符），并非宏观基本问题本身。
  - **C. 链路终止**：错误。这是特定点对点协议（如 PPP 协议）在通信结束时的状态机阶段（建立物理连接 $\rightarrow$ 鉴别 $\rightarrow$ 网络层配置 $\rightarrow$ 链路终止），不属于所有链路层通用的三大基本问题。
  - **D. 受控接入**：错误。属于介质访问控制（MAC，Medium Access Control）协议中的一种类别（如集中控制的轮询技术），与基本问题无关。

- **【期末防坑提示】**：
  1. **易混淆陷阱：把“实现手段”当成了“根本问题”**：
     - “字节填充”、“零比特填充（5 1 填 0）”是用来解决“**透明传输**”的技术手段；
     - “CRC 循环冗余检验”是用来解决“**差错检测**”的技术手段；
     - 它们是**手段**，而“**封装成帧、透明传输、差错检测**”才是**三大基本问题**！
  2. **“无比特差错”不等于“可靠传输”**：
     - CRC 差错检测只能保证接收端收到的帧**没有比特被改写（无比特差错）**。
     - 但如果整个帧在网络中丢失了、重复了、失序了，以太网等现代数据链路层并不负责重传（直接扔掉），可靠传输通常由传输层的 TCP 协议来保障！

   A. 10.005S

### 题目解析与答案

- **【正确答案】**：A. 10.005S

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把网络传输这批数据，想象成**收费站放行一列超长车队并跑完高速公路（两段独立耗时）**：
  1. **发送时延（网卡推数据上路） = 收费站把一整列车队全部放行出站需要多久**：  
     车队总长度是 $10^8\text{ bit}$，收费站每秒只能放行 $10^7\text{ bit}$。即使第一辆车（第一个比特）刚出门，只要最后一辆车（最后一个比特）还在站里，就算没发完。  
     所以收费站放完所有车需要耗时：$10^8 / 10^7 = \mathbf{10\text{ 秒}}$。
  2. **传播时延（信号在线路上传播） = 最后一辆车在高速公路上跑完 1000 公里需要多久**：  
     车队以电磁波的速度（接近光速，$2 \times 10^8\text{ 米/秒}$）在光纤/网线上飞奔。这只取决于**路有多长（距离）**以及**速度有多快**，与车队长不长毫无关系！  
     $1000\text{ km} = 10^6\text{ 米}$，跑完耗时：$10^6 / (2 \times 10^8) = \mathbf{0.005\text{ 秒}}$。
  3. **总时延 = 发送时延 + 传播时延**：  
     两段耗时累加：$10\text{ 秒} + 0.005\text{ 秒} = \mathbf{10.005\text{ 秒}}$。

- **【手把手计算 / 解题步骤】**：
  1. **提取已知物理量并统一单位（极其关键）**：
     - 数据长度 $L = 10^8\text{ bit}$
     - 发送速率（数据率/带宽）$R = 10^7\text{ bps} = 10^7\text{ bit/s}$
     - 链路距离 $D = 1000\text{ km} = 1000 \times 10^3\text{ m} = 10^6\text{ m}$
     - 传播速率 $v = 2 \times 10^8\text{ m/s}$
  2. **分步计算发送时延（Transmission Delay / 传输时延）**：
     $$\text{发送时延} = \frac{\text{数据长度 } L}{\text{发送速率 } R} = \frac{10^8\text{ bit}}{10^7\text{ bit/s}} = 10\text{ s}$$
  3. **分步计算传播时延（Propagation Delay）**：
     $$\text{传播时延} = \frac{\text{链路长度 } D}{\text{传播速率 } v} = \frac{10^6\text{ m}}{2 \times 10^8\text{ m/s}} = 0.005\text{ s}$$
  4. **求时延之和**：
     $$\text{总时延} = \text{发送时延} + \text{传播时延} = 10\text{ s} + 0.005\text{ s} = 10.005\text{ s}$$

- **【各选项逐一深度剖析】**：
  - **A. 10.005S**：**正确**。严格遵循标准公式与国际单位换算推导得出。
  - **B. 10.05S**：错误。常见计算失误：把传播时延的小数点点错，例如误算成 $10^6 / (2 \times 10^8) = 0.05\text{ s}$（少了一个 0），或者是未注意 $1/200 = 0.005$ 误写为 $0.05$。
  - **C. 100.05S**：错误。双重失误：既把发送时延多算了一个 0（$10^8 / 10^7 = 100$），又把传播时延的小数点算错。
  - **D. 100.005S**：错误。经典低级失误：指数相除出现算术笔误，误把 $10^8 / 10^7$ 当成了 $100$。

- **【期末防坑提示】**：
  1. **单位换算第一大坑：千米（km）必须换算为米（m）**：
     - 题干给出距离是 $1000\text{ km}$，而波速是 $2 \times 10^8\text{ m/s}$。**两者的长度单位不一致**！
     - 必须先将 $1000\text{ km}$ 乘以 $1000$ 换算成 $10^6\text{ m}$，若直接用 $1000 / (2 \times 10^8)$，结果将产生 1000 倍的致命误差。
  2. **严防“发送时延”与“传播时延”概念倒置**：
     - 发送时延（传输时延）：在**主机/网卡内部**发生，受**发送速率（带宽）**影响；
     - 传播时延：在**传输介质（光纤/铜线）**上发生，受**介质物理特性（光速/光纤波速）**影响；
     - **提高网络带宽（如从 10Mbps 升级到 100Mbps），只能缩短发送时延，绝不可能改变电磁波在光纤中的传播速度！**（期末概念判断题高频考点）。


8. (单选题, 5分) IP 服务的3个主要特点是（  ）？
   A. 可靠、面向连接和尽最大努力投递
   B. 不可靠、面向无连接和尽最大努力投递
   C. 不可靠、面向连接和全双工
   D. 可靠、面向无连接和全双工

---

### 题目解析与答案

- **【正确答案】**：B. 不可靠、面向无连接和尽最大努力投递

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把 IP 数据报传输想象成**到街边邮筒寄一封“普通平信”**：
  1. **面向无连接（Connectionless）**：  
     寄信前，你**完全不需要提前给收件人打电话建立通道**（不像打电话必须双方都在线才能通话）。写好收件人地址，贴上邮票，直接扔进邮筒就走。每个数据包独立找路。
  2. **尽最大努力交付（Best-Effort Delivery）**：  
     邮递员叔叔（路由器）非常尽职尽责，只要公路通着、地址清楚，他一定会想方设法把你这封信转发到下一站邮局，绝不会故意丢弃。
  3. **不可靠（Unreliable）**：  
     但如果路上遇到山体滑坡导致信件丢失、或者信件受潮字迹模糊、或者先寄的信反而比后寄的信还晚到（丢包、出错、重复、乱序），**邮局绝不承担赔偿责任，也绝对不负责自动帮你重写一封补寄**。IP 协议只管竭力传输，不负责保障百分之百送达。
  4. **为什么这么设计？（互联网大师的智慧）**：  
     正因为 IP 协议把网络层做得极其“简单轻巧（不可靠、无连接）”，网络中间的成千上万台路由器才不需要维护复杂的连接状态和沉重的重传缓存，路由器造价大幅降低、转发速度飞快！至于“可靠传输”，谁的应用程序需要（如网页下载、文件传输），谁就在端系统的**传输层（TCP 协议）**自己去加确认和重传！

- **【核心机制与设计哲学手把手拆解】**：
  根据 RFC 791 定义，TCP/IP 体系中网际协议 IP 提供的是一种**无连接的数据报服务（Datagram Service）**：
  1. **面向无连接**：  
     - 发送端在发送数据报之前，不需要同接收端以及中间路由器建立端到端的虚电路或物理连接。
     - 每个 IP 数据报都是独立寻址、独立路由选路的，前后分组没有依赖，因此同一批数据报可能经过不同的物理路径到达目的地。
  2. **不可靠**：  
     - IP 数据报在传输过程中，可能遭遇以下情况：**分组丢失、损坏、失序或重复**。
     - IP 首部虽然有“首部检验和（Header Checksum）”，但只检验 IP 首部本身是否损坏，发现损坏直接丢弃，**IP 层本身绝不提供自动重发与纠错机制**。
  3. **尽最大努力交付（Best-Effort）**：  
     - 网络节点（路由器）不会随意丢弃数据报；只要路由器有缓冲区空闲、链路正常，就全力以赴向前转发，直到网络过载发生拥塞才不得不丢弃。

- **【各选项逐一深度剖析】**：
  - **A. 可靠、面向连接和尽最大努力投递**：错误。“可靠”和“面向连接”是传输层 **TCP 协议**的标志性特征，且“可靠”与“尽最大努力交付”在语义上是互斥的（尽力交付意味着不承诺可靠交付）。
  - **B. 不可靠、面向无连接和尽最大努力投递**：**正确**。精准概括了 IP 协议的核心服务模型与设计基石。
  - **C. 不可靠、面向连接和全双工**：错误。“面向连接”和“全双工通信（两端可同时收发）”属于 TCP 连接的属性，IP 层没有连接也不存在全双工连接概念。
  - **D. 可靠、面向无连接和全双工**：错误。概念严重杂糅，“可靠”与“全双工”均非 IP 特点。

- **【期末防坑提示】**：
  1. **不要望文生义误解“尽最大努力交付”**：
     - 很多同学误以为“尽最大努力”等于“一定会送到/绝对可靠”，这是最常见的语文直觉陷阱！
     - **“尽最大努力”恰恰是“不可靠”的官方委婉表达**：潜台词是“我已经尽力了，如果中间路由器爆仓丢包了，我概不负责”。
  2. **两大核心协议的鲜明对比（期末必考填空与选择）**：
     - **网络层 IP**：**无连接、不可靠、尽最大努力交付**（数据报服务）。
     - **传输层 TCP**：**面向连接、可靠交付、全双工通信、面向字节流**。
     - **传输层 UDP**：**无连接、不可靠、尽最大努力交付、面向报文**（常被称为“IP 协议的高层门牌号映射”）。


9. (单选题, 5分) 主机A和主机B间已建立一个TCP连接，主机A向主机B发送了两个连续的TCP段，分别包含800字节和600字节的有效载荷，第一个TCP段的序号字段值为400，主机B（主机乙）正确接收到两个段后，发送给主机A（主机甲）的确认号是（ ）？
   A. 1400
   B. 1600
   C. 1800
   D. 2000

---

### 题目解析与答案

- **【正确答案】**：C. 1800

- **【零基础通俗秒懂思维 / 生活比喻】**：
  把 TCP 传输字节想象成**按页码寄送并催更连载小说（累积确认机制）**：
  1. **TCP 是“面向字节流”的**：  
     给传输的每一个字节都按顺序编了一个像小说页码一样的唯一编号。
  2. **第一个快递包裹（序号 400，装了 800 字节）**：  
     - “序号值为 400”代表这个包裹里的第一页是**第 400 页**。
     - 里面装了 800 字节，所以这个包裹装的内容是**第 400 页 到 第 1199 页**（注意：$400 + 800 - 1 = 1199$）。
  3. **第二个快递包裹（紧接着发送，装了 600 字节）**：  
     - 既然紧密相连，它的第一页自然是**第 1200 页**。
     - 里面装了 600 字节，所以这个包裹装的内容是**第 1200 页 到 第 1799 页**（$1200 + 600 - 1 = 1799$）。
  4. **收件人回复确认号 ack = “催更下一页”**：  
     - 主机 B 完整无误地收齐了从第 400 页一直到第 1799 页的全部数据。
     - **TCP 确认号 ack 的铁律定义**：“**期望收到对方下一个报文段的第一个数据字节的序号**”！
     - 既然收齐了前 1799 页，B 回复给 A 的确认号必然是：$1799 + 1 = \mathbf{1800}$！

- **【手把手计算 / 解题步骤】**：
  1. **明确 TCP 序号与确认号的标准定义**：
     - **序号字段（Sequence Number, seq）**：占 32 位，指出本报文段所发送的数据的**第一个字节的序号**。
     - **确认号字段（Acknowledgment Number, ack）**：占 32 位，是**期望收到对方下一个报文段的第一个数据字节的序号**。若确认号为 $N$，则表明到序号 $N-1$ 为止的所有数据都已正确收到。
  2. **计算各段字节编号区间**：
     - **第 1 个 TCP 段**：
       - 起始序号：$seq_1 = 400$
       - 载荷长度：$Len_1 = 800\text{ 字节}$
       - 字节区间为：$[400, 400 + 800 - 1] = [400, 1199]$
     - **第 2 个 TCP 段**：
       - 起始序号：$seq_2 = 1200$
       - 载荷长度：$Len_2 = 600\text{ 字节}$
       - 字节区间为：$[1200, 1200 + 600 - 1] = [1200, 1799]$
  3. **求最终确认号 ack**：
     - 主机 B 累计正确接收到的最后一个连续字节序号为 $1799$。
     - 期望收到的下一个字节序号：
       $$ack = 1799 + 1 = 1800$$
     - 或者直接利用累积确认极速公式：
       $$ack = \text{起始序号 } seq_1 + Len_1 + Len_2 = 400 + 800 + 600 = 1800$$

- **【各选项逐一深度剖析】**：
  - **A. 1400**：错误。初学者常见遗忘起点失误：只计算了两个段的载荷总大小 $800 + 600 = 1400$，却忘记了第 1 个段不是从 0 号开始编号，而是从 400 号开始。
  - **B. 1600**：错误。计算逻辑混乱的无依据干扰项。
  - **C. 1800**：**正确**。由 $400 + 800 + 600 = 1800$ 精确计算得出，表示 1800 之前的字节已全部正确接收，期望接收 1800 号。
  - **D. 2000**：错误。部分同学误以为加完后还要再加上载荷或者四舍五入凑整，无任何计算依据。

- **【期末防坑提示】**：
  1. **牢记确认号的数学含义：期望值 = 已收最大序号 + 1**：
     - 若已知已收到最后一字节为 $K$，则 $ack = K + 1$。
     - 若确认号为 $ack = M$，说明前 $M - 1$ 个字节均已安全到达。
  2. **累积确认（Cumulative Acknowledgment）特性**：
     - TCP 不需要对每一个收到的字节或段都逐一回传单独确认，而是可以在收到多个连续报文段后，**只发送最后一个合并的确认号**（本题即连续收到 2 个段后合并发回 $ack = 1800$）。
  3. **极简 5 秒秒杀套路**：
     - 只要题目说“连续发送且均正确接收”，直接拿：**初始序号 + 所有段的有效载荷之和**，一步得出正确答案！
