# 01 递归本质与调用栈机制

> **⚡ 30 秒速记**
> - **本质**：递归是把原问题逐次归结为**结构相同、规模较小**的子问题，最终由最简单情形回传解。
> - **三要素**：① 结构相同的子问题；② 递归调用次数有限；③ 必须具备明确的边界出口（Base Case）。
> - **双阶段律**：
>   - 递归调用**之前**的代码在【递推压栈】阶段执行（正向顺序）；
>   - 递归调用**之后**的代码在【回归弹栈】阶段执行（逆向反序）。
> - **空间与溢出铁律**：递归额外空间开销 = **系统调用栈的最大瞬时深度**（非调用总次数）。即使逻辑出口正确，若单链深度突破线程物理栈限制（通常 ~1MB-8MB），仍会抛出 `StackOverflowError`。

---

## 一、心智模型：递推与回归的物理过程

计算机在执行递归时，并不存在特殊的“自我克隆”机制，而是统一通过操作系统的**调用栈（Call Stack）**分配**栈帧（Stack Frame）**。

一个完整的递归执行必须经历对称的两个阶段：

```
       递推阶段 (Wind / 前序推进)                回归阶段 (Unwind / 后序回溯)
原问题 n=3 ──(压栈1)──> n=2 ──(压栈2)──> n=1 ────┤
                                                │ (触碰 Base Case: 1!=1)
原问题最终解 <──(弹栈1)── n=2解 <──(弹栈2)── n=1解 ◄──┘
```

---

## 二、底层机理：栈帧（Stack Frame）的开辟与销毁

### 1. 每次调用时系统在栈中压入了什么？
当程序执行 `call func(x)` 时，系统在调用栈顶分配一个栈帧，包含：
1. **返回地址 (Return Address)**：被调函数结束后，CPU 的程序计数器（PC）该跳回调用方代码的哪一行；
2. **实参与形参 (Parameters)**：传递进来的具体参数副本；
3. **局部变量 (Local Variables)**：当前函数作用域内声明的变量。

### 2. 栈帧空间与生命周期示意图
以阶乘 `fact(3)` 为例：

```
      +-------------------------------------------+
栈顶  | fact(1) 栈帧: n=1, 返回地址: fact(2)第8行  |  <-- 触发 Base Case，开始弹栈
      +-------------------------------------------+
      | fact(2) 栈帧: n=2, 返回地址: fact(3)第8行  |
      +-------------------------------------------+
      | fact(3) 栈帧: n=3, 返回地址: main()第3行   |
      +-------------------------------------------+
栈底  | main()  栈帧: 调用 fact(3)                |
      +-------------------------------------------+
```

## 三、代码执行顺序：递归前后的“镜像反序”现象

课件第 10 页经典阶乘与追踪代码展示了极其重要的执行时序规律：

```java
public static void printTrace(int n) {
    if (n <= 0) {
        return; // 边界条件：不再下潜，开始逐层返回
    }
    
    // 【阶段 1：递归调用之前】-> 压栈执行，自顶向下（正向）
    System.out.print(n + " "); 

    printTrace(n - 1); // 递归调用点：当前执行挂起，等待下一层返回

    // 【阶段 2：递归调用之后】-> 弹栈执行，自底向上（逆向）
    System.out.print(n + " "); 
}
```

调用 `printTrace(3)` 的输出结果：
$$\mathbf{3 \quad 2 \quad 1 \quad 1 \quad 2 \quad 3}$$

- **前半部分 `3 2 1`**：是递推压栈时由顶至底顺序打印；
- **后半部分 `1 2 3`**：是回归弹栈时由底至顶逆向打印。

## 四、期末考点与面试避坑指南

### 1. 递归死循环 vs 物理栈溢出（常见陷阱题）
- **误区**：“只要写了 `if (n == 0) return;` 就一定安全。”
- **真相**：
  - 逻辑正确不等于物理安全。
  - 单向深递归（如 $n=100000$ 的阶乘、深层链表），系统栈深度线性增长达到 $10^5$，会直接撑爆系统默认栈容量（Java 报 `java.lang.StackOverflowError`，C++ 报 `Segmentation Fault`）。
  - **面试应对**：遇到深线性递归，工程优化方案是**转化为迭代循环**或**利用显式栈模拟**。

### 2. 空间复杂度度量法则
- 递归算法的辅助空间复杂度等于**调用树的最大高度（最大瞬时栈深度）**，而不是递归调用的总节点数！
  - 线性递推（如阶乘）：深度为 $O(n)$，空间复杂度为 $O(n)$；
  - 折半递推（如二分查找）：虽然整体在递归，但最大深度仅为 $O(\log n)$，空间复杂度为 $O(\log n)$。
