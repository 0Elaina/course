# 04 并查集及其复杂度优化

> **⚡ 30 秒速记**
> - **核心功能**：查掌门（`find`）+ 并门派（`unite`）。
> - **双重优化**：
>   - **路径压缩**：`parent[x] = find(parent[x])`，递归回溯时将沿途节点直接拍扁连到根。
>   - **按大小合并**：小树挂在大树下，防止树高膨胀。
> - **复杂度**：双优化后 $m$ 次操作均摊时间复杂度为 $O(m \cdot \alpha(n))$，几乎等同于常数 $O(1)$。

---

## 一、是什么（一句话定义）
并查集（Disjoint Set Union, DSU）是一种用于高效管理一组不相交集合，支持“查找元素所属集合代表元（Find）”与“合并两个集合（Union）”的树形数据结构。

---

## 二、为什么这样设计
如果用普通数组或位向量表示集合，合并操作需要遍历全集（$O(n)$）。采用树形双亲表示法，配合“加权合并”与“路径压缩”，可将 $m$ 次操作的均摊复杂度降至接近严格常数级的 $O(m \cdot \alpha(n))$。

---

## 三、关键技术与标准 C++ 模板

### 1. 核心操作原理
- **双亲表示法**：一维数组 `parent[i]` 存储节点 $i$ 的直接父节点编号；当 `parent[i] == i` 时表示该节点为集合代表元（树根/掌门）。
- **优化 1：路径压缩 (Path Compression)**
  - 在 `find` 向上寻根的过程中，顺手将递归路径上的所有节点直接连到最终根节点，实现树的高度的极致扁平化。
- **优化 2：按大小/按秩合并 (Union by Size/Rank)**
  - 将节点数较少的树挂在节点数较多的树根下，避免树的高度单链退化。

### 2. 标准 C++ 工业级模板
```cpp
#include <vector>
#include <numeric>

class UnionFind {
private:
    std::vector<int> parent;
    std::vector<int> sz; // 记录各连通块的大小

public:
    // 构造函数：初始化 n 个独立元素
    UnionFind(int n) : parent(n + 1), sz(n + 1, 1) {
        std::iota(parent.begin(), parent.end(), 0); // 初始各成一派：parent[i] = i
    }

    // 查掌门 + 路径压缩（一行递归拍扁树高）
    int find(int x) {
        if (parent[x] == x) return x;
        return parent[x] = find(parent[x]); // 回溯时将沿途直接指向根
    }

    // 并门派 + 按大小加权合并
    bool unite(int x, int y) {
        int rootX = find(x);
        int rootY = find(y);
        if (rootX == rootY) return false; // 已在同一集合

        // 小树挂在大树下
        if (sz[rootX] < sz[rootY]) {
            std::swap(rootX, rootY);
        }
        parent[rootY] = rootX;
        sz[rootX] += sz[rootY];
        return true;
    }

    // 判断两元素是否连通
    bool is_connected(int x, int y) {
        return find(x) == find(y);
    }
};
```

### 3. 时间与空间复杂度
- **时间复杂度**：单次操作均摊时间复杂度为 $O(\alpha(n))$，其中 $\alpha(n)$ 为阿克曼反函数。
  - 在实际物理世界所有可能输入下（即使 $n = 10^{80}$），$\alpha(n) \le 4$，等同于严格常数 $O(1)$。
- **空间复杂度**：$O(n)$（仅需 `parent` 和 `sz` 数组）。

## 四、易错点与混淆辨析

| 易错点 | 原因与后果 | 解决方案 |
| :--- | :--- | :--- |
| **单链退化** | 不做优化时，依次合并 $1 \to 2 \to \dots \to n$ 导致树退化为单链表，单次查找退化为 $O(n)$。 | 引入路径压缩或按大小合并。 |
| **路径压缩时机** | 路径压缩发生在**递归回溯阶段**。未被 `find` 访问到的旁支不会自动扁平化。 | 在每次关键查找时均调用 `find`。 |
| **合并时忘记找根** | 直接写 `parent[x] = y` 而非 `parent[rootX] = rootY`，会导致整棵子树关系丢失。 | 必须先调用 `find(x)` 和 `find(y)` 找到树根后再连接。 |

## 五、与其他概念的关系
- **Kruskal 最小生成树算法**：使用并查集快速判断待加入的边是否构成环路。
- **动态图连通性分析**：网络设备连接判断、社交网络朋友圈子图划分。
