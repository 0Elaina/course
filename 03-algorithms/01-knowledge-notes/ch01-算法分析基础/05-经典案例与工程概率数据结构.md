# 05 经典案例与工程概率数据结构

> **⚡ 30 秒速记**
> - **布隆过滤器四大铁律**：零漏报（无假阴性，说不存在 100% 不存在）；有误报（有假阳性，说存在只是可能存在）；$O(k)$ 极速查询；天生不支持删除（支持删除需改用计数布隆过滤器）。
> - **核心应用**：Redis 缓存穿透防护、海量黑名单与爬虫 URL 过滤（省 90% 内存）。
> - **百鸡降维思维**：通过等式代换与数学消元，算法从 $O(n^3) \to O(n^2) \to O(n)$ 飞跃。

## 一、布隆过滤器 (Bloom Filter)：高并发海量数据过滤神器

### 1. 为什么需要它？（业务痛点）
海量数据判断存在性（如 10 亿个恶意 URL 黑名单、已爬取网页 URL 去重）：
- **传统哈希表 (`unordered_set`)**：每个字符串 64 字节，10 亿个需占用上百 GB 内存，机器直接 OOM。
- **布隆过滤器**：仅用几十到数百 MB 的**位数组 (Bit Array)**，以极低的误判率为代价，换取惊人的内存节约与 $O(k)$ 常数查询性能！

### 2. 底层架构与执行流程
- **结构组成**：一个长度为 $m$ 的二进制位数组（初始全为 0）+ $k$ 个独立的哈希函数。
- **添加元素**：通过 $k$ 个哈希函数计算出 $k$ 个下标，将位数组对应位置**全部置为 1**。
- **查询元素**：同样计算出 $k$ 个下标，检查位数组状态：
  - **任一位置为 0** $\implies$ **该元素绝对不存在！**（100% 可靠）
  - **全部位置为 1** $\implies$ **该元素“可能存在”**（可能发生假阳性误报）。

### 3. 核心概念剖析：假阳性 vs 假阴性

| 术语 | 英文 | 实际情况 | 系统判定 | 通俗解释 | 布隆过滤器中表现 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **真阳性** | True Positive | 存在 | 判定为“存在” | 正常命中 ✅ | 会发生 |
| **真阴性** | True Negative | 不存在 | 判定为“不存在” | 正常拦截 ✅ | 会发生 |
| **假阳性** | **False Positive** | **实际不存在** | **误判为“存在”** | **误报 / 虚警 ❌** | **会发生！（即误判率，可通过增大位数组压低）** |
| **假阴性** | **False Negative** | **实际存在** | **漏判为“不存在”** | **漏报 / 漏网 ❌** | **绝对不会发生！（概率为 0）** |

### 4. 为什么普通布隆过滤器不支持删除？
位数组中的某个 `1` 很可能是被多个不同的合法元素**哈希碰撞后共同共享**的。若直接清零，会破坏其他元素的判定状态，导致其他元素被“误判为不存在”（产生假阴性致命错误）。
- **工程改进**：如果业务强制要求支持删除，需改用 **计数布隆过滤器 (Counting Bloom Filter)**，将每个 bit 改为可增减计数的数字。

### 5. 后端高并发经典实战：防 Redis 缓存穿透

```
客户端请求 (查询 Key)
       │
       ▼
[布隆过滤器预检] ──(判定不存在)──> [直接返回 404 拦截，绝不查库]
       │
   (判定可能存在)
       ▼
  [查 Redis 缓存] ──(命中)──> [返回数据]
       │ (未命中, 极少数)
       ▼
 [查 MySQL 数据库]
```
- **防护原理**：黑客制造大量数据库不存在的非法 ID（如负数 ID）刷接口，布隆过滤器瞬间以 $O(k)$ 拦截在最前线，保护底层 MySQL 免遭打崩。

## 二、百鸡问题的工程降维思维：从 $O(n^3)$ 到 $O(n)$

百钱买百鸡问题（公鸡 5 钱、母鸡 3 钱、小鸡 1/3 钱）：
$$\begin{cases} x + y + z = 100 \\ 5x + 3y + \frac{1}{3}z = 100 \end{cases}$$

面对多变量多约束问题，算法优化展现了典型的**三次降维跃迁**：

### 阶段 1：暴力三层枚举 —— $O(n^3)$
三重 `for` 穷举 $x, y, z$，运算 $100^3 = 10^6$ 次，规模扩大后极易超时。

### 阶段 2：利用等式约束降维 —— $O(n^2)$
利用数量守恒 $z = 100 - x - y$，只需枚举 $x, y$ 两层循环，$z$ 直接算得。

### 阶段 3：数学代入消元，极致降维 —— $O(n)$
联立两式消去 $z$，推出 $y = \frac{100 - 7x}{4}$ 与 $z = \frac{300 + 3x}{4}$。
- **只需要 1 层 for 循环枚举 $x$**，且步长受 $(100 - 7x) \bmod 4 == 0$ 约束，计算次数缩减至十几次，实现线性乃至常数级的飞跃！

### 💡 工程映射与实践
在日常业务开发中，面对双重或多重循环查询（如 LeetCode 两数之和、批量数据对账），切忌直接写嵌套循环，优先利用**等式转化（`needed = target - current`）配合哈希表查找**，实现从 $O(n^2) \to O(n)$ 的降维。
